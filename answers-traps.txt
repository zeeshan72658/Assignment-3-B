1. Which registers contain arguments to functions? For example, which register holds 13 in main's call to printf?
Answer:
Registers a0 through a7 hold integer/pointer function arguments (a0 for the first argument, a1 for the second, up to a7). Floating-point arguments are passed in fa0 through fa7.
In main's call to printf ("%d %d\n", f(8)+1, 13), register a2 holds the value 13.

2. Where is the call to function f in the assembly code for main? Where is the call to g? (Hint: the compiler may inline functions.)
Answer:
There are no jump instructions (no jal or jalr) to function f or function g in main. The compiler completely inlined both functions and evaluated f(8)+1 at compile-time: g(8) returns 8+3=11, so f(8) returns 11, and f(8)+1 equals 12. The compiler emitted the instruction `li a1, 12` to load 12 directly into register a1.

3. At what address is the function printf located?
Answer:
Address 0x00000000000006bc (0x6bc).

4. What value is in the register ra just after the jal to printf in main?
Answer:
Address 0x0000000000000034 (0x34), which is the address of the instruction immediately following `jal 6bc <printf>` in main (`li a0, 0`).

5. Run the following code:
unsigned int i = 0x00646c72;
printf("H%x Wo%s", 57616, (char *) &i);
What is the output?
If RISC-V were instead big-endian what would you set i to in order to yield the same output?
Would you need to change 57616 to a different value?
Answer:
The output is: "He110 World"
Explanation:
- 57616 in hexadecimal is 0xe110, so "H%x" formats it as "He110".
- In little-endian RISC-V, 0x00646c72 is laid out in memory starting from lowest address (&i) as:
  Byte 0: 0x72 ('r')
  Byte 1: 0x6c ('l')
  Byte 2: 0x64 ('d')
  Byte 3: 0x00 ('\0')
  Thus, "Wo%s" prints "World".
If RISC-V were big-endian, byte 0 is the most significant byte. To obtain the same bytes in memory (0x72, 0x6c, 0x64, 0x00), i would need to be set to 0x726c6400.
No, 57616 does not need to be changed because 57616 is a numeric value loaded into register a1. Register values are numbers, and their arithmetic values are independent of the system's memory byte-ordering endianness.

6. In the following code, what is going to be printed after 'y='? Why does this happen?
printf("x=%d y=%d", 3);
Answer:
The value printed for y will be whatever value was previously residing in register a2.
According to the RISC-V calling conventions, printf expects its format string in a0, the first argument for %d (x) in a1, and the second argument for %d (y) in a2. Since the caller only supplied 3 as an argument, register a1 was set to 3, but register a2 was never set by the caller. printf still reads register a2 for the second "%d", resulting in whatever leftover value was stored in a2.
